OpenAuto

Turn a Linux PC or Raspberry Pi into an Android Auto head unit. Modernized fork: Qt6, FFmpeg/VAAPI hardware video, unified CMake build.

View on GitHub Get started

Features

📺 480p – 1080p @ 30/60 FPS

Hardware-accelerated H.264 decode via VAAPI/FFmpeg with automatic software fallback.

🔊 Full audio

Media, System and Speech playback plus microphone input, over Qt or RtAudio backends.

👆 Touch & buttons

Touchscreen, buttons, scroll wheel and rotary input forwarding.

📡 USB + Wi-Fi

USB hotplug/AOAP handshake, wireless mode via the phone's head-unit server, and a Bluetooth companion daemon.

What's new vs upstream

Forked from f1xpl/openauto (2018, Qt5/C++14). Headline changes — full details in the README:

  • Single unified build — aasdk/ vendored in-tree; one cmake --build . --target build compiles library + app.
  • Qt5 → Qt6 multimedia stack (Multimedia, Bluetooth, Wayland client, FFmpeg plugin APIs).
  • VAAPI hardware video decode with driver auto-detection.
  • Modern Boost (io_context, verified 1.92), C++17, CMake 4, protobuf 36 + Abseil.
  • RtAudio output backend, LTO release flags, refreshed docs.

Install dependencies

Arch Linux (verified: Boost 1.92, Qt 6.11, protoc 36.1):

sudo pacman -S --needed base-devel cmake ninja pkgconf \
  boost boost-libs \
  qt6-base qt6-multimedia qt6-multimedia-ffmpeg qt6-connectivity \
  qt6-declarative qt6-wayland wayland \
  ffmpeg libva libva-utils libusb openssl protobuf abseil-cpp grpc \
  rtaudio libx11 libxrandr libxext libglvnd egl-wayland

Ubuntu 24.04+, Fedora 41+ and openSUSE commands are in the README §5.

Build

cd openauto
cmake -DCMAKE_BUILD_TYPE=Release .
cmake --build . --target build -j$(nproc)
# → bin/autoapp  bin/btservice  aasdk/lib/libaasdk.a  aasdk/lib/libaasdk_proto.a

Run

./bin/btservice &   # Bluetooth calling features (optional)
./bin/autoapp       # plug the phone in over USB and accept the prompts

First run: open Settings for resolution/FPS, audio backend and input options. For USB permissions (udev rule), Wi-Fi mode and troubleshooting, see the README §§7–9.
